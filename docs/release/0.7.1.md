# Stable Release — 0.7.1

Release: `aibridge-0.7.1.transport.zip`

## Highlights

- **Manager explorer search fixed.** `ResourceExplorerService::search()` used flat `OR:` criteria keys, which
  OR-ed the whole clause (including `deleted = 0`), so a search matched almost every resource; and it passed
  query options as `getCollection()`'s `$cacheFlag`, so `limit`/`sortby` were ignored. It now uses a grouped OR
  search and an explicit `newQuery()` with `limit()`/`sortby()`; the TV filter is a join on
  `modTemplateVarResource` (no `contentid` materialization).
- **Manager tree and profiles limits fixed.** `ResourceExplorerService::tree()` and `RestApi::profiles()` no
  longer pass `limit`/`sortby` as the cache flag; both build a `newQuery()` and honour their documented
  limits/ordering (tree: `menuindex`; profiles: `id`, max 100).
- Patch release: bug fixes only, no scope, route, schema, setting or response-shape change.
