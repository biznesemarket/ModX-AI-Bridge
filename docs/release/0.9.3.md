## Highlights

- **Publish approval bound to the caller.** `SecurityDecisionPipeline::isApprovedForChange()` now loads the
  referenced `ChangeRequest`, requires it to be a `resource.publish` change, requires the caller's
  `profile_id` to match the change's profile (for profile-scoped principals), and requires the change's
  `resource_id` to match the requested resource. Previously any approved `Approval` row could authorize
  publishing an arbitrary resource — including from another profile — and could be replayed. `RestApi`,
  `ResourceExecutionService` and `McpServer` now pass the target `resource_id` into the pipeline.
- **Manager-connector MCP channel propagated.** The trusted `channel` is forwarded from the MCP transport into
  the tool-handler requests, so manager-channel mutations pass the execution-layer pipeline instead of being
  rejected `ip_not_allowed`. No privilege change (it failed closed before).
- **Workflow verification mismatch fixed for `published`.** `ChangeRequestService::create()` drops `published`
  for create/update, so the recorded `after_json` matches what execution applies and the change no longer
  fails post-execution verification after committing the other fields.
- **MCP tool contract.** `resource_publish` now declares `change_id` as required, matching the pipeline.
- **Docs/tests.** SDK identity note and `install-package.php` examples corrected; new cross-profile and
  wrong-resource publish rejection tests; new integration tests clean up their fixtures.
- Patch release: security and correctness fixes; no new scope, route, schema, migration or setting.
