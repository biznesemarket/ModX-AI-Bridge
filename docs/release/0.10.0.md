# Stable Release — 0.10.0

Release: `aibridge-0.10.0.transport.zip`
Tag: `v0.10.0`
Built by: `scripts/release-candidate.php` (invoked in the MODX container with `MODX_ROOT=/var/www/html`)

## Highlights

- **Errors no longer leak internals.** REST/MCP responses and `jobs.error_json` carry stable codes and
  messages; the raw exception text is redacted and kept only in the audit trail / MODX log (Defect #36).
- **Profile-scoped idempotency and rate limiting.** Both unique indexes now begin with `profile_id`, the
  rate-limit read filters on the caller's profile, and migration `003_profile_scoped_unique_indexes.sql`
  upgrades existing installations (Defects #37).
- **Idempotency-Key is bounded** at 190 characters at the REST and execution boundaries (`400
  idempotency_key_invalid` instead of a database 500); the MCP schemas document `maxLength` (Defect #38).
- **Job timeouts are terminal.** A timeout is never requeued (no replay of a possibly-committed mutation), and
  a cooperative `JobDeadline` stops the execution service before the mutation transaction when the budget is
  spent (Defect #40).
- **Cache invalidation is scoped** to the resource page cache and its context's resource/alias map instead of
  the whole MODX `db` partition (Defect #41).
- **Console projections.** `changes()`/`approvals()` return projected, decoded rows; console service is
  `readonly` (Defects #42/#43).
- **Dead code removed.** Unreferenced stub classes were deleted; the `static-contract` gate fails if they
  return (Defect #39).
- Minor release: one migration and one additive error code; routes, settings and operations are unchanged.
  SDK `User-Agent` `0.9` → `0.10`; SDK/package `clientInfo` → `0.10.0`.
