## Highlights

- **Operations Console limits/ordering fixed.** All eight `OperationsConsoleService` list methods passed
  their options as `getCollection()`'s cache flag, so `limit` (and the documented ordering) were silently
  ignored and the overview returned unbounded rows in arbitrary order. Each list now builds an `xPDOQuery`
  with `limit()` (1..500); `jobs`, `audit`, `fingerprints` and `changes` are ordered by `created_at DESC`
  and `approvals` by `requested_at DESC`.
- **Rollback processor fails as JSON.** `ResourceRollbackProcessor` no longer lets `RollbackService`
  exceptions (unknown/invalid snapshot, missing target resource) escape `Processor::run()`; it returns
  `failure('Rollback failed.', ['code' => 'rollback_failed'])`. A missing `snapshot_id` reports
  `invalid_snapshot`.
- **Manager resource tree hardened.** `ResourceExplorerService::tree()` guards empty collections and its
  depth semantics are now documented and locked by tests: `depth` is the number of nested `children` levels
  (0 = flat list; deeper levels are capped at 100 items), and a soft-deleted node hides its subtree.
- **Coverage.** New `OperationsConsoleServiceTest` (limits, DESC ordering, no token secrets, readiness),
  new `ResourceRollbackProcessorTest` (auth, permission, snapshot validation, unknown snapshot, restore +
  audit) and `ResourceExplorerServiceTest::testTreeDepthExpandsNestedChildrenAndHidesDeletedSubtrees`.
- Patch release: bug fixes and tests only; no scope, route, schema, migration or setting change.
