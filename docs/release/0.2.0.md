## Highlights

- **Resource read-back API.** `GET /api/ai/v2/resources/{id}` returns a whitelisted projection of a persisted
  resource (title/content/template/parent/published/timestamps) through the SecurityDecisionPipeline under the
  new `resource:read` scope; missing or soft-deleted resources return `404 resource_not_found`. The same
  operation backs the new `resource_read` MCP tool. `getResource()` is available in both SDKs, and the
  TypeScript live HTTP E2E now verifies the state after an update instead of parsing job `result_json`.
- **`aibridge_version` system setting.** The version is packaged as a real MODX setting (20 settings total);
  `/health`, `/ready`, the Operations Console and `scripts/readiness.php` report the setting value with the
  previous code fallback.
- Additive minor: new route, scope, MCP tool and setting; no schema/migration change, existing tokens keep
  working (they need `resource:read` explicitly for read-back).
