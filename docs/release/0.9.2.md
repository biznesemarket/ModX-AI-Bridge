# Stable Release — 0.9.2

Release: `aibridge-0.9.2.transport.zip`
Tag: `v0.9.2`
Built by: `scripts/release-candidate.php` (invoked in the MODX container with `MODX_ROOT=/var/www/html`)

## Highlights

- **Publish-approval bypass closed.** `ResourceExecutionService::sanitizePayload()` accepted `published`, so a
  principal with `resource:write` could set `published = 1` through `resource.update`/`resource.create` and
  bypass the approval-gated `resource.publish` operation. `published` is no longer writable; publish state is
  set only by the publish branch. Regression: `testUpdateCannotBypassPublishApproval`.
- **Deterministic site discovery.** `TemplateInspector`, `TVInspector`, `ChunkInspector` and
  `SnippetInspector` passed `sortby` as `getCollection()`'s cache flag (ignored), so the fingerprint could
  change without content changes. Each inspector now builds an `xPDOQuery` with an explicit
  `sortby(name|templatename, ASC)`. Regression: `SiteDiscoveryDeterminismTest`.
- **Workflow lists.** `WorkflowProcessor::listChanges()/listApprovals()` now honour `limit(200)` and
  `created_at`/`requested_at DESC` (previously options-as-cacheFlag).
- **CIDR hardening.** `IpAllowlist` rejects malformed prefix lengths (`/33` on IPv4, `/129` on IPv6,
  negative/non-numeric) instead of matching every address. Regression: `testRejectsMalformedPrefixLengths`.
- **Manager-connector MCP hardened.** `processors/mcp.class.php` now requires manager authentication and the
  `aibridge_manage` permission, derives the principal from the authenticated MODX user and the real transport
  peer, and never trusts request-supplied `scopes` or `_client_ip`.
- **MCP publish approval forwarding.** `McpServer::callTool()` forwards `approval_id`/`change_id` into the
  security pipeline, so `resource_publish` succeeds with a valid approved change (and is denied without one).
  Regression: `McpPublishApprovalTest`.
- Patch release: security and correctness fixes; no new scope, route, schema, migration or setting.
