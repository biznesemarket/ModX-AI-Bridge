## Highlights

- **Secret template variables can be withheld from read-back.** New `aibridge_redacted_tvs` setting (JSON
  array of TV names): those keys are omitted from the `tvs` map returned by `GET /api/ai/v2/resources/{id}`,
  the MCP `resource_read` tool and `modx://resource/{id}`, so a TV holding a secret never reaches a client
  with `resource:read`. Default `[]` keeps the previous behaviour.
- **Deeper `parent` traversal.** The recursive list filter accepts `depth` up to 50 (was 10) and stops with
  `400 too_many_descendants` when a subtree exceeds the 5000-id materialization budget instead of building
  an unbounded set. The MCP schema derives its `maximum` from `ResourceReadService::LIST_DEPTH_MAX`.
- **Hard job stop.** The CLI worker runs each claimed job in a supervised child process and SIGKILLs it once
  the job's `timeout_seconds` budget is spent. The child owns its database connection, so the transaction is
  rolled back; the job is recorded as a non-retryable `job_timeout` and its in-progress idempotency key is
  released. Child stderr is bounded, redacted and attached to the audit diagnostic; `--inline` restores the
  cooperative single-process mode.
- Minor release: one additive setting and one additive error code; routes, existing settings and operations
  are unchanged. SDK `User-Agent` `0.10` → `0.11`; SDK/package `clientInfo` → `0.11.0`.
